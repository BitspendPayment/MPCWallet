# MPCWallet

A Taproot-enabled Multi-Party Computation (MPC) Bitcoin wallet.

This repository implements a distributed wallet architecture designed to ensure a full private key never exists in a single location. By utilizing **Distributed Key Generation (DKG)** and **FROST (Flexible Round-Optimized Schnorr Threshold)** signatures, the client and server collaboratively authorize spends without compromising trust assumptions.

To the Bitcoin network, transactions generated by this MPC setup are represented as Taproot key-path spends via BIP-341 tweaks. This keeps on-chain footprint close to standard single-key usage while improving privacy and fee efficiency.

## Architecture & Separation of Concerns

The codebase is modularized to isolate stateless cryptographic primitives from stateful orchestration, policy logic, and user interface concerns.

- `threshold/` (Cryptography Engine): Mathematical core for DKG, FROST share generation/aggregation, and BIP-341 tweak computation. Decoupled from transport and persistence.
- `server/` (Coordinator & Policy Engine): Dart gRPC backend (`server/bin/server.dart`) that orchestrates protocol rounds, maintains server-side share state, enforces authentication/policy constraints, and integrates with Electrum/Bitcoin RPC services.
- `client/` (Wallet Orchestrator): Dart client library driving DKG/refresh flows, local coin selection, transaction construction, and collaborative signing.
- `ap/` (User Interface): Flutter frontend that wraps `client/` wallet flows.
- `protocol/` & `protos/`: Shared protobuf definitions (`protos/mpc_wallet.proto`) and generated Dart gRPC stubs.
- `e2e/`: Integration tests and regtest orchestration.

## Core Protocol Flow

1. **Distributed Key Generation (DKG):** Client and server execute a 3-round DKG to derive shares and group public key material.
2. **Transaction Building:** The client selects UTXOs and builds a candidate transaction from current wallet state.
3. **FROST Signing:** Client and server complete a 2-round threshold signing flow (nonce commitments, then signature share aggregation) to produce a valid BIP-340 Schnorr signature.
4. **Broadcast:** The finalized Taproot transaction is broadcast to the network.

## Local Development Setup

### Prerequisites

- Dart SDK
- Flutter SDK (for `ap/`)
- Docker & Docker Compose
- Protocol Buffers compiler (`protoc`)

### 1. Start the Local Blockchain

Use Dockerized Bitcoin `regtest` + `electrs`.

```bash
# Start local regtest stack
make regtest-up

# Stop local regtest stack
make regtest-down
```

### 2. Fetch Dependencies

Install dependencies for each package:

```bash
(cd threshold && dart pub get)
(cd protocol && dart pub get)
(cd client && dart pub get)
(cd server && dart pub get)
(cd e2e && dart pub get)
(cd ap && flutter pub get)
```

### 3. Generate Protobuf Stubs

If you modify `protos/mpc_wallet.proto`, regenerate Dart bindings:

```bash
make proto
```

### 4. Run the Server

```bash
make server-run
```

## Testing

Tests are colocated under each package's `test/` directory.

- Unit tests (example):

```bash
(cd threshold && dart test)
(cd client && dart test)
```

- Integration tests:

```bash
# Ensure regtest stack is up
make regtest-up

# Run e2e tests
(cd e2e && dart test)
```
